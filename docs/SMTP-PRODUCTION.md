# מדריך SMTP לפרודקשן — תפוזיאל

> **עברית קודם, אנגלית אחר כך.** כמו המוצר עצמו.  
> אותו יצרן, אותה חברה: **Shaltiel Industries / WhiteNo1se** — CMS + CRM + מעבדה קשורים; לא מוצרים זרים זה לזה.

מדריך קצר. אחרי **v1.95** המייל מחוזק (timeouts, תקרת יום, מניעת הזרקת כותרות).  
ההגדרה: **אדמין → אינטגרציות → מייל (SMTP)**.

---

## 1. מה SMTP עושה אצלנו

| שימוש | צריך |
|--------|------|
| **קמפייני CRM** (פילוח / רשימה) | `enabled` + מארח + משתמש + סיסמה → `smtpReady` |
| **התראה על פנייה מטופס** | אותו דבר **וגם** אימייל יעד (`to`) → `leadReady` |

סודות ב־`config/notify.json` (לא ב־git). מונה יומי: `config/notify-usage.json`.

---

## 2. לפני שמחברים

1. דומיין האתר עם **SPF** (ואם אפשר **DKIM** / **DMARC**) אצל ספק המייל.
2. כתובת **From** ששייכת לדומיין (לא `noreply@gmail` אם שולחים בשם העסק).
3. תקרת יום סבירה (ברירת מחדל **500**) — מוניטין לפני נפח.
4. אף פעם לא `tlsAllowInsecure` בפרודקשן.

---

## 3. מתכונים קצרים

### Gmail / Google Workspace

1. הפעילו אימות דו־שלבי.
2. צרו **App Password** (סיסמת אפליקציה) — לא סיסמת החשבון.
3. בתפוזיאל:
   - מארח: `smtp.gmail.com`
   - פורט: `465` + SSL **או** `587` בלי סימון SSL (STARTTLS)
   - משתמש: כתובת Gmail המלאה
   - סיסמה: סיסמת האפליקציה
4. **בדוק חיבור** → **שלח בדיקה**.

מגבלות Google קשוחות על נפח. לקמפיינים גדולים — SES / ספק טרנזקציוני.

### Amazon SES

1. אמתו דומיין ב־SES; צאו מ־sandbox אם צריך.
2. צרו SMTP credentials בקונסול.
3. מארח לפי אזור, למשל: `email-smtp.eu-west-1.amazonaws.com`
4. פורט `587` (או `465` + SSL).
5. From = כתובת/דומיין מאומת ב־SES.

### Resend / Postmark / SendGrid / ספק דומה

1. צרו API SMTP או SMTP user אצל הספק.
2. העתיקו host / port / user / pass מהתיעוד שלהם.
3. ודאו ש־From מאומת אצלם.
4. בדקו חיבור + שליחת בדיקה בתפוזיאל.

### שרת אחסון (cPanel / Hostinger וכו׳)

1. צרו תיבת מייל בדומיין (`site@yourdomain.com`).
2. host לרוב: `mail.yourdomain.com` או מה שמופיע ב־cPanel.
3. פורט `465`+SSL או `587`.
4. אם התעודה שבורה — **תקנו תעודה**, אל תפעילו TLS לא מאומת בפרודקשן.

---

## 4. אחרי החיבור — זרימת CRM

1. **הפעילו CRM** (אדמין → אנשי קשר).
2. ודאו ש־**SMTP מוכן** במסך קמפיינים (כרטיס ירוק).
3. בנו **פילוח** (למשל תחום עניין + יש מייל + הסכמה).
4. **דיוור לפילוח** או קמפיין חדש עם קהל = פילוח.
5. שליחה רק למי עם **הסכמה** — הסרה בלחיצה אחת בכל הודעה.

זה הקו: רלוונטי, לא הצפה.

---

## 5. תקלות נפוצות

| תסמין | מה לבדוק |
|--------|-----------|
| «SMTP לא מוכן» | enabled, host, user, סיסמה נשמרה |
| Authentication failed | App Password / SMTP user נכון; לא סיסמת אתר |
| Timeout | חומת אש / פורט חסום; נסו 587 מול 465 |
| נשלח אבל spam | SPF/DKIM/DMARC; From תואם דומיין |
| «מגבלת שליחה יומית» | `maxPerDay` או המתינו ליום הבא (מונה ב־UTC) |
| בדיקה נכשלה בלי `to` | לשליחת בדיקת התראה צריך אימייל יעד; לקמפיין מספיק smtpReady |

---

## 6. אבטחה (לא מתפשרים)

- סיסמה לא חוזרת ב־API (`hasPass` בלבד).
- אין CR/LF בכתובות/נושא.
- תעודת TLS מאומתת בפרודקשן.
- תקרת יום מגנה על המוניטין (ועל חשבון חינמי).
- קמפיין לא נכנס לתור בלי SMTP מוכן.

קוד: `src/notify.js` · בדיקות: `npm run test:notify` / `node scripts/smoke-notify.js`.

| # | צעד | למה |
|---|-----|-----|
| 1 | **מדריך זה + SMTP אמיתי** על אתר staging | מלחמת מוניטין נלמדת רק עם שרת אמיתי |
| 2 | **פיקסל על WP אמיתי** (Hostinger WhiteNo1se) + `site_id` | CRM על אתרי האויב — הערך בלי «תעברו CMS» |

| 5 | **מודולי פרימיום / תמיכה** (אבא במכירות) | ליבה חינמית; כסף על תמיכה, אחסון, תוספים |
| 6 | **חשבוניות ישראליות** (סבב פיננסי נפרד) | ערך עסקי גבוה — לא לערבב עם CRM באמצע |
